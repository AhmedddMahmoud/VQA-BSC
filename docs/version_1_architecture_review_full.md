# Version 1 Architecture Review (Full Project Walkthrough)

This document reviews the **entire current codebase** for your Version 1 classical multi-hop VQA baseline, including architecture, data flow, scripts, debug utilities, and current dataset wiring.

---

## 1) Project Scope and Design Intent

This repository is intentionally constrained to a **Version 1 classical baseline**:

- frozen pretrained `ResNet-50` visual encoder,
- `GRU`/`BiLSTM` question encoder,
- **2-hop** question-conditioned spatial attention,
- **top-K answer classification** (configured as top-1000 in contracts),
- no retrieval, no OCR, no external knowledge, no generative decoding.

The code emphasizes:

- clear module boundaries,
- reproducible config-driven runs,
- debug visibility (attention weights + shape checks),
- first proving correctness before chasing performance.

## 3) Configuration System

### File: `src/utils/config.py`

Defines a dataclass `V1Config` containing all major knobs:

- data and path settings,
- model dimensions,
- training hyperparameters,
- subset sizes,
- freeze/precomputed feature toggles,
- output locations.

Supports:

- `V1Config.from_json(path)`
- `to_json(path)`
- `as_dict()`

This is the single source of truth used by train/eval/debug scripts.

### Config files currently present

- `configs/version1_vqa.json`: default expected structure under `data/vqa_v2/...`
- `configs/version1_smoke.json`: tiny synthetic/smoke run setup
- `configs/version1_real.json`: wired to your local `datasets/...` paths

### Important contract values

Current train contract enforcement in code requires:

- `answer_vocab_size == 1000`
- `num_hops == 2`
- positive subset sizes

That enforcement is implemented in `src/train/train_vqa.py::enforce_v1_contracts` and reused by debug scripts.

## 4) Data Pipeline

### File: `src/datasets/vqa_dataset.py`

#### `VQAv2Dataset`

Responsibilities:

1. Load questions JSON and annotations JSON.
2. Join by `question_id`.
3. Compute majority answer from VQA answer list.
4. Filter samples whose majority answer is not in top-K answer vocab.
5. Build sample dict with:
   - `question_id`, `question`, `image_id`, `answer_idx`
6. Serve `__getitem__` outputs with:
   - tokenized/padded question ids,
   - question length,
   - label,
   - image tensor **or** precomputed features.

Image loading behavior:

- tries `COCO_train2014_{id:012d}.jpg`,
- falls back to `COCO_val2014_{id:012d}.jpg`.

Stats exposed:

- `dataset.stats["loaded"]`
- `dataset.stats["skipped_not_in_topk"]`

#### `SyntheticVQADataset`

Produces random-but-structured data for smoke/debug runs with same key schema as real pipeline.

#### `vqa_collate_fn`

Batches all fields and returns keys expected by model/train scripts:

- `question_ids`, `question_lengths`, `labels`,
- metadata lists (`question_ids_list`, `question_texts`, `image_ids`),
- either `images` or `image_features`.

## 6) Model Architecture

### File: `src/models/image_encoder.py`

Class: `FrozenResNet50Encoder`

- Uses torchvision ResNet-50 up to final conv stage (`[:-2]`), no global pool/classifier.
- Outputs flattened spatial tokens:
  - conv map: `(B, 2048, 7, 7)`
  - tokens: `(B, 49, 2048)`
- Can freeze all conv parameters.
- Includes fallback to `weights=None` if pretrained load fails.
- Debug option `return_feature_map=True` returns both tokens and conv map.

### File: `src/models/question_encoder.py`

Class: `QuestionEncoder`

- Embedding layer + packed-sequence recurrent encoder (`GRU` or `LSTM/BiLSTM`).
- Produces fixed question vector of shape `(B, hidden_dim)`.
- For bidirectional mode: concatenates last forward/backward states.
- Debug option `return_intermediate=True` returns:
  - `embedded` (token embeddings),
  - `question_vector`.

### File: `src/models/attention.py`

Class: `SpatialAttentionHop`

Implements attention over 49 visual regions:

- projects visual token and query vector,
- computes scalar score per region,
- softmax over regions,
- weighted sum -> attended visual vector.

Inputs/outputs:

- in: `visual_tokens (B,49,2048)`, `query_vector (B,hidden_dim)`
- out: `attended (B,2048)`, `attention_weights (B,49)`

### File: `src/models/multihop_vqa.py`

Class: `MultiHopVQAModel`

Composition:

1. Image branch (live encoder or precomputed features).
2. Question branch (`QuestionEncoder`).
3. Two attention hops (`num_hops` from config, contract enforces 2).
4. Hop update: `state = state + W(attended)`.
5. Fusion: `concat(state, attended_last)`.
6. MLP classifier -> logits over answer vocab.

Returned outputs (normal mode):

- `logits`
- `attention_weights` shape `(B, num_hops, 49)`
- `visual_tokens`
- `question_vector`

Returned outputs (debug mode):

- `debug.feature_map` (when raw images used)
- `debug.question_embedding`
- `debug.attended_per_hop` shape `(B, num_hops, 2048)`
- `debug.fusion`

## 7) Training and Evaluation Runtime

### File: `src/train/train_vqa.py`

Key responsibilities:

- parse args (`--config`, `--synthetic`)
- enforce V1 contracts
- build real or synthetic dataloaders
- instantiate model/criterion/optimizer
- run train and val epochs
- compute top-1 accuracy counters
- save failure examples each epoch
- save best checkpoint

Checkpoint includes:

- model weights
- config snapshot
- question vocab
- answer vocab
- best val accuracy

### File: `src/train/eval_vqa.py`

- loads checkpoint and config
- rebuilds model and val dataset
- computes eval loss and accuracy
- saves qualitative failures to JSONL

---

## 8) Debug and Verification Utilities

### File: `src/debug/inspect_vqa_samples.py`

Purpose: verify dataset integrity before training.

What it prints/checks:

- split summary (loaded/skipped/drop ratio)
- per-sample question text, token ids, answers, label index, decoded answer
- image path existence warnings
- label-index/decoded-answer consistency assertions

Failure behavior: designed to fail loudly on missing files or mapping mismatches.

### File: `src/debug/debug_forward_pass.py`

Purpose: run exactly one batch and verify tensor contracts.

Checks include:

- all key shape assertions
- attention softmax sum per hop ~ 1
- debug-intermediate availability

Covers both synthetic and real modes.

### File: `src/debug/overfit_small_batch.py`

Purpose: prove learnability on tiny subset.

Outputs:

- initial loss
- periodic step loss + batch accuracy
- final tiny-set loss/accuracy
- checkpoint + predictions JSONL

Includes warning when overfit signal is weak.

## 11) End-to-End Runtime Flow (Real Mode)

1. Load config (`version1_real.json`).
2. Build question vocab from train questions.
3. Build top-1000 answer vocab from train annotations.
4. Build train/val `VQAv2Dataset` with answer filtering.
5. DataLoader batches via `vqa_collate_fn`.
6. Model forward:
   - image -> `(B,49,2048)`
   - question -> `(B,512)`
   - hop1+hop2 attention
   - classifier -> `(B,1000)` logits
7. Cross-entropy with class index labels.
8. Save checkpoint/failure artifacts.

## 13) Known Practical Risks (from code-level review)

1. `train_vqa.py` currently has no CLI flags for runtime subset override (e.g., `--subset-train`, `--subset-val`); subset sizing is config-only.
2. If `use_precomputed_features=True`, `.npy` shape assumptions are not explicitly asserted in dataset loader (downstream assertions in debug script catch most shape issues).
3. Real-data path correctness depends entirely on config file consistency with local folder layout.

None of these are architecture violations; they are operational considerations.
